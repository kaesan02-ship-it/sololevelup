# 휴대폰·PC 동기화

## 현재 연결 상태

2026-10-12: 기존 프로젝트 `uotscostmadmnaypdxus`에 연결했다. 사용자가 SQL Editor에서 테이블·RLS·저장 함수를 적용했고 실제 Supabase 계정과 공개 앱에서 동기화를 검증했다.

- 공개 앱: https://kaesan02-ship-it.github.io/sololevelup/
- 프로젝트: https://supabase.com/dashboard/project/uotscostmadmnaypdxus
- 기본 공개 연결 정보: `lib/public-project.ts` (관리자 비밀 키·DB 비밀번호 없음)
- 설정을 바꿀 때는 `NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 함께 지정한다. GitHub Actions 변수 쌍을 설정하면 기본값보다 우선하며 재빌드가 필요하다.

추가로 SQL을 실행하거나 키를 다시 입력할 필요 없이 앱에서 가입·로그인을 시작할 수 있다. Supabase 관리 대시보드 계정과 앱 로그인 계정은 별개다. 이 프로젝트의 이메일 가입은 현재 메일 확인 없이 세션을 발급하도록 설정돼 있다. 실제 이메일 발송·인증 메일 도달은 이번 검사 대상이 아니다.

## 처음 두 기기 연결하기

1. 기존 기록이 있는 휴대폰에서 앱을 새로고침하고 **설정 → 기기 간 동기화 → 계정 만들기**를 선택한다. 앱에서 사용할 이메일·비밀번호를 정한다. 이미 앱 계정을 만들었다면 로그인한다.
2. 첫 기기에서는 **이 기기의 기록 사용**을 눌러 기록과 사진을 클라우드에 저장한다.
3. PC나 두 번째 기기에서 같은 앱 계정으로 로그인한다.
4. 두 번째 기기에서는 **클라우드 기록 사용**을 선택해 내려받는다.

첫 연결은 두 기기의 기록을 자동으로 합치지 않는다. 교체할 기록이 있는 기기는 먼저 JSON 백업을 내려받는다. 기존 기록이 있는 첫 기기를 올린 뒤 두 번째 기기에서 내려받는 순서를 권장한다.

온라인 기록은 자동 동기화하며 **지금 동기화**로 확인할 수 있다. 오프라인 기록은 해당 브라우저에 저장하고 연결 후 전송한다. 같은 기록을 양쪽에서 각각 수정하면 자동 덮어쓰기 대신 충돌을 표시한다. 유지할 기록을 선택하기 전에 각 기기에서 백업한다. 사진은 동기화 문서와 JSON 백업에 포함된다. 로그아웃은 해당 기기의 기록을 지우지 않는다.

## 실제 검사 결과

공개 HTTPS 앱과 실제 Supabase API를 사용했다. 휴대폰 화면(393×851)과 PC 화면(1440×1000)의 별도 Chromium 브라우저 저장소를 사용했으며, 실제 안드로이드 OS/네이티브 사진 선택기 검사는 아니다.

- 검증용 두 계정의 실제 이메일 인증 API 및 앱 로그인 성공.
- 첫 기기에서 사진·기록을 올리고 두 번째 기기에서 동일 내용 확인.
- 다른 계정의 첫 계정 문서 조회는 빈 결과, 수정은 실제 문서를 바꾸지 못함(RLS).
- 비로그인 문서 접근은 401/권한 거부.
- 잘못된 null 버전은 `invalid_version`, 오래된 버전은 `sync_conflict`로 저장 거부.
- 오프라인에서 독서 기록을 추가한 뒤 연결하면 다른 기기로 전달됨.
- 서로 다른 오프라인/온라인 수정은 충돌로 멈추고, 명시적으로 클라우드 기록을 선택하면 해결됨.
- 테스트 중 UI의 이전 ‘동기화 완료’ 표시를 즉시 읽는 것만으로 서버 저장 완료를 판정하지 않았다. 실제 서버의 기록·버전이 변경된 것을 기다려 확인했다.

검사에는 임시 검증용 계정 2개만 사용했다. 검증 기록과 사진은 해당 계정 문서에서 비웠다. 검증용 Auth 계정과 비어 있는 검증 문서는 남아 있다. 공개 키에는 관리자 계정 삭제 권한이 없어 자동 삭제하지 않았으며, 개인 계정·기존 `growth_logs` 등 다른 데이터는 조회하거나 변경하지 않았다. 검증용 비밀번호·세션 토큰은 문서나 Git에 저장하지 않는다.

## 새 프로젝트로 옮길 때

새 프로젝트에서 `supabase/setup.sql`을 실행하고 공개 URL·Publishable key 쌍을 교체한 다음 재배포한다. service_role/secret 키는 브라우저 앱에서 사용하지 않는다. 다른 프로젝트로 옮겨도 기존 클라우드 기록이 자동 이관되는 것은 아니므로 먼저 JSON 백업을 만든다.
