# 전체 구현 검토 — 2026-10-12

## 결론

개인용 로컬 앱의 핵심 흐름을 검토하고 발견한 데이터 보호 문제를 수정했다. 현재 자동 검증은 통과했다. 실제 Supabase 서비스와 공개 HTTPS 배포, 실제 안드로이드 기기 검증이 남아 있으므로 운영 환경까지 완성·검증됐다는 의미는 아니다.

## 발견하여 수정한 문제

| 중요도 | 상황과 영향 | 수정·검증 |
| --- | --- | --- |
| 높음 | 같은 브라우저의 두 탭에서 오래된 화면을 저장하면 새 기록 전체를 덮어쓸 수 있었음 | IndexedDB 트랜잭션 안에서 편집 기준 데이터와 최신 저장 데이터를 비교. 충돌 시 저장 중단, 최신 데이터 로드, 입력 중인 기록값 보존. 두 탭에서 10쪽과 20쪽을 기록해 충돌 후 재시도 시 30쪽이 보존되는 브라우저 테스트 통과 |
| 높음 | 최초 클라우드 연결 전에는 동기화 revision이 없어, 내려받는 동안 만든 로컬 기록을 감지하지 못했음 | revision과 실제 데이터 스냅샷을 함께 비교. 클라우드 조회를 지연시키고 로컬 7쪽을 입력한 후 덮어쓰기를 거부하는 모의 동기화 테스트 통과 |
| 보통 | 앱을 켜둔 채 자정이 지나면 재렌더 전까지 오늘 날짜·완료 상태가 전날에 머무름 | 30초 간격 및 창 포커스 복귀 시 날짜 갱신. 서울 자정을 넘긴 날짜·완료 상태 브라우저 테스트 통과 |
| 보통 | 시간대를 뒤로 바꾸면 이전 시간대의 정상 기록을 미래 기록으로 판단해 백업 복원·동기화에서 거부할 수 있었음 | 백업 날짜 검증에 현재 전 세계에서 가능한 최신 현지 날짜(UTC+14)를 사용. 새 기록 입력은 사용자 시간대의 오늘까지로 제한. 정상 백업 복원과 실제 미래 날짜 거부 테스트 통과 |
| 낮음 | 설정에 ‘기기 간 동기화 미지원’이라는 이전 설명이 남아 있었음 | 클라우드 연결 후 동기화 가능하며 연결 전 데이터는 해당 브라우저에 저장됨을 안내 |
| 낮음 | 모달 키보드 포커스 순환 대상에서 출처 링크가 빠짐 | 링크를 순환 대상에 포함 |

추가로 저장 직전 백업과 동일한 데이터 구조 검증을 적용하고, React 상태 갱신 전 중복 저장을 막는 즉시 잠금을 추가했다. 충돌 시 데이터를 자동 병합하지 않으며 최신 기록을 확인한 뒤 다시 저장하도록 안내한다.

## 확인한 기능

- 상태창: XP 계산, 기간 비교, 스냅샷 선택·필터·고정 항목.
- 나의 스탯: 활동일·연속 기록·목표·캘린더·분류별 차트·상세 기록 연결.
- 나의 기록/성장 분석: 사용자 항목 추가, 기록 작성·수정·삭제, 측정값 교체 확인, 항목 순서·보관·복구, 기간별 계산.
- 설정: 분류 관리, 프로필 사진, JSON 백업·복원, CSV 내보내기.
- 모바일: Android Chrome 모의 환경 360/393/412px 세로와 900px 가로의 넘침·터치·사진·폰트·입력 화면 확인. 생성된 모바일 스크린샷도 확인.
- 오프라인: 서비스 워커 앱 셸·로컬 폰트·재실행·기록 저장.
- 동기화: 모의 두 기기의 연결·다운로드·오프라인 수정·충돌 감지·명시적 해결 및 최초 다운로드 중 로컬 수정 보호.
- 의존성: `npm audit --omit=dev`에서 알려진 운영 의존성 취약점 0개 보고. 보안 전반이 입증됐다는 의미는 아님.

## 남은 검증과 제한

1. Supabase 프로젝트 생성·SQL 적용·공개 환경 변수 연결 후 실제 가입 메일, 로그인, 두 기기 동기화, 계정 간 RLS 격리를 검증해야 한다. 현재 통과한 것은 모의 API 테스트다.
2. 공개 HTTPS 배포 후 실제 안드로이드 Chrome에서 설치·카메라/사진 선택·키보드·회전·오프라인을 확인해야 한다. 에뮬레이션은 Android OS 또는 삼성 인터넷 실기기 테스트가 아니다.
3. 사진 기반 캐릭터 자동 생성은 구현하지 않았으며 사진/이미지 업로드를 지원한다.
4. 추천 활동은 자료별 전문·초록·서지 확인 범위가 다르다. 미확인 자료와 적용 한계는 `research/ACTIVITY-EVIDENCE.md` 및 활동별 설명에 표시한다. XP와 차트는 건강·능력의 과학적 점수가 아니다.
