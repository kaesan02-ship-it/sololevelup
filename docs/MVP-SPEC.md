# 솔로 레벨업 — 초기 버전 작업명세서

작성일: 2026-10-12 · 상태: 구현 전 검토안 · 대상: 개인용 모바일 우선 웹앱

> 현재 버전은 화이트톤·사진 프로필로 변경했고 그림 캐릭터는 제거했다. 홈 화면 설치와 동기화 코드를 추가했다. 최신 범위는 [구현 현황](IMPLEMENTATION.md)과 [동기화 연결 안내](SUPABASE-SETUP.md)를 참고한다. 아래는 최초 계획을 보존한 문서다.

## 1. 목표와 결정 사항

생각나는 성장 항목을 자유롭게 추가하고, 기록을 남기고, 과거의 나와 현재의 나를 한 화면에서 비교한다. 캐릭터 레벨은 실천의 누적을 나타내며 실제 신체 능력이나 지능을 평가하지 않는다.

첫 버전은 기본 세트 선택 → 기록 → 변화 확인 → 레벨 상승의 한 바퀴를 완성한다. 사용자는 개발 지식 없이 항목 이름·단위·분류·목표를 설정할 수 있다.

이번 제안은 이전의 계정 기반 출시안보다 범위를 줄인다. 우선 로그인 없이 같은 브라우저에 데이터를 보관하는 개인 체험 버전을 만든다. 기기 간 동기화와 계정은 실제 사용 후 다음 단계로 진행한다. 이 문서는 제안이며 앱 구현·배포는 아직 진행하지 않았다.

성공 기준: 기본 세트로 시작하기 1분 이내, 익숙한 항목 입력 약 10초 이내를 사용성 목표로 삼고, 2주간 사용한 뒤 입력 불편과 비교 정보의 유용성을 평가한다.

## 2. 유사 서비스 조사와 반영

2026-10-12 공식 공개 자료를 직접 조회했다. 별도 검색엔진 도구가 없어 알려진 후보들의 공식 주소와 공개 저장소를 조사했다. 서비스 전체를 직접 사용하거나 최신 출시 화면을 검증한 것은 아니다.

| 서비스 | 확인한 근거와 구성 | 우리 서비스에 반영할 설계 판단 |
| --- | --- | --- |
| Habitica | 공식 README에서 일상을 RPG로 취급하고 성공 시 레벨 상승, 실패 시 HP 감소, 골드와 장비 보상을 제공한다고 설명 | 실천→경험치→레벨의 짧은 보상 흐름을 채택. HP 감소·장비·전투는 초기 범위에서 제외 |

## 3. 초기 기본 세트

시작 화면에서 아래 항목을 선택하거나 전부 해제하고 직접 추가할 수 있다. 사용자 기록이나 목표값을 임의로 채우지 않는다. 예시 목표는 제안이며 선택하지 않으면 목표 없이 기록한다.

| 항목 | 분류 | 방식 / 단위 | 요약 | 기본 방향 | 선택 가능한 목표 예시 |
| --- | --- | --- | --- | --- | --- |
| 체중 | 신체 | 측정 / kg | 최신값·추이 | 기록만 | 사용자가 목표 체중 지정 |
| 골격근량 | 신체 | 측정 / kg | 최신값·추이 | 기록만 | 사용자 설정 |
| 푸시업 최대 기록 | 운동 | 최고 기록 / 회 | 기간 최대·개인 최고 | 증가 | 한 번에 30회 |
| 독서 | 학습 | 누적 / 쪽 | 기간 합계 | 증가 | 주 100쪽 |
| 집중 공부 | 학습 | 시간 / 분 | 기간 합계 | 증가 | 주 120분 |
| 스트레칭 | 생활 | 완료 체크 | 완료 일수 | 기록만 | 주 3일 |

기본 세트의 목적은 다섯 가지 기록 방식을 체험하는 것이다. 푸시업 하루 총량이 필요하면 별도의 누적형 항목을 추가한다. 기본 분류는 신체·운동·학습·생활이며 직접 분류를 추가할 수 있다.

## 4. 기능 범위

### 반드시 포함

- 기본 항목 선택 또는 빈 상태로 시작하기.
- 사용자 정의 항목 생성·이름 수정·정렬·첫 화면 고정·보관·삭제.
- 다섯 기록 방식: 측정, 최고 기록, 수량 누적, 시간 누적, 완료 체크.
- 분류 추가·이름 수정. 삭제 시 연결 항목은 미분류로 이동.
- 숫자, 날짜, 선택 메모로 기록 추가·수정·삭제. 체크형은 한 번 눌러 완료/취소.
- 전체 현황, 최근 7일/30일 비교, 항목 상세 그래프와 기록 목록.
- 선택적 목표: 측정/최고 기록의 목표값, 누적/시간의 주간 총량, 체크의 주간 완료 일수.
- 경험치·레벨, 기본 업적 3개, 브라우저 영구 저장.
- JSON 백업·복원, CSV 기록 내보내기.

### 다음 버전

계정·클라우드 동기화, 설치형 PWA와 오프라인 앱 실행, 알림, 건강 앱 연동, 단계형 프로젝트, 자유로운 능력치 배분, 레이더 차트, AI 보고서, 소셜·랭킹, 캐릭터 장비·전투, 복잡한 반복 일정, 목표 범위 유지 기능.

초기에는 주간 목표를 홈에서 보여주는 것으로 퀘스트를 대신한다. 별도의 퀘스트 생성기나 보상 상점을 만들지 않는다.

## 5. 항목과 기록 규칙

항목 생성 필수 입력은 이름·기록 방식이다. 단위는 유형별 기본값을 제안하되 측정/수량은 변경 가능하다. 분류·목표·아이콘·성장 방향은 선택 사항이다. 분류 미지정은 미분류, 방향 미지정은 기록만으로 처리한다.

- 이름은 공백 제거 후 1~40자, 단위 1~12자, 메모 최대 500자.
- 수량·시간·최고 기록은 0 이상 유한 숫자, 시간은 정수 분, 측정은 음수도 가능한 유한 숫자로 처리한다. 소수는 최대 3자리. 특정 건강 목표를 강요하지 않는다.
- 증가/감소 방향은 측정·최고 기록에서 지원. 감소형 최고 기록은 최소값이 개인 최고다.
- 측정형은 항목당 하루 1개. 같은 날 저장하면 기존 기록 수정 여부를 보여준다.
- 누적·시간·최고 기록은 하루 여러 개 가능. 완료 체크는 항목당 하루 하나이며 다시 누르면 취소한다.
- 미래 날짜는 허용하지 않고 과거 기록은 허용한다. 날짜 기준은 프로필 시간대이며 초기 제안은 기기 시간대다. 한국 사용자에게는 Asia/Seoul을 사용한다. 기록 날짜는 시간대 변경으로 자동 이동시키지 않는다.
- 저장 중 중복 클릭을 막고 실패하면 입력 내용을 유지한다. 저장 실패를 성공으로 표시하지 않는다.
- 기록이 있는 항목의 방식·단위 변경은 막고 새 항목 생성을 안내한다. 이름·분류·목표는 수정 가능하다.
- 보관은 기록과 경험치를 유지하며 활성 목록에서 숨긴다. 영구 삭제는 영향받는 기록 수를 표시하고 확인 후 삭제한다.
- 새 항목에 예시 데이터를 자동 삽입하지 않는다. 디자인 검토용 예시 수치는 실제 데이터와 분리한다.

## 6. 성장 계산

홈의 기본 기간은 최근 7일(오늘 포함), 비교 구간은 직전 7일이다. 30일도 동일한 방식으로 연속된 같은 길이 구간을 비교한다. 두 구간의 실제 날짜를 표시하며 오늘 데이터는 입력 중일 수 있음을 알린다.

| 방식 | 기간 대표값 | 비교 규칙 |
| --- | --- | --- |
| 측정 | 기간 내 가장 최근 값 | 두 기간 대표값 차이. 각 측정 날짜도 표시 |
| 최고 기록 | 증가형은 최대, 감소형은 최소 | 두 기간 최고값 차이. 전체 개인 최고는 별도 표시 |
| 누적·시간 | 기록된 값의 합 | 기간 합계 차이. 기록한 날 수를 함께 표시 |
| 완료 체크 | 완료한 고유 날짜 수 | 기간별 완료 일수 차이 |

누락은 0이 아니다. 한 구간 전체에 기록이 없으면 비교 불가로 표시한다. 누적 합계는 '기록된 합계'로 표기하여 미기록 활동까지 추정하지 않는다. 수치형 그래프는 빈 날짜를 0으로 채우지 않는다. 이전값이 0이면 퍼센트는 생략하고 절대 차이만 보여준다.

홈의 고정 카드는 최대 4개, 전체 항목 수에는 인위적인 작은 제한을 두지 않는다. 방향이 기록만이면 색으로 좋고 나쁨을 판정하지 않는다. 목표가 있는 측정값은 목표와의 거리도 보여주되 감량량 자체에 추가 보상하지 않는다.

주간 목표는 프로필 시간대의 월요일~일요일 기준이며 최근 7일 비교와 구분해서 표시한다. 목표 수정은 현재 진행률에만 반영하고 과거 보상을 소급 생성하지 않는다.

## 7. 경험치·레벨·업적

초기 규칙은 단순하게 고정한다.

- 항목별 하루 유효 기록이 있으면 10 XP, 전체 하루 최대 50 XP.
- 유효 기록: 측정은 유효 숫자, 누적·시간·최고 기록은 0보다 큰 값, 체크는 완료 상태.
- 하루 XP = min(50, 유효 기록이 있는 고유 항목 수 × 10).
- 총 XP는 날짜별 XP 합계, 레벨 = 1 + floor(총 XP / 100), 현재 레벨 진행률 = 총 XP mod 100.
- 같은 기록 반복 저장이나 항목 이름 변경은 XP를 늘리지 않는다.
- 수정·삭제·복원 후 원본 기록에서 재계산한다. 삭제로 XP가 줄 수 있지만 쉬었다는 이유로 감소하지 않는다.
- 과거 날짜 기록도 동일 규칙으로 반영한다. 자기 기록용이므로 부정행위 방지 시스템은 만들지 않는다.
- 첫 기록, 7일의 기록(연속일 필요 없음), 첫 개인 최고 갱신의 업적 3개 제공. 업적은 추가 XP 없이 배지만 부여한다.
- 첫 개인 최고 갱신은 최고 기록형에서 기존 최고보다 엄격하게 나아진 두 번째 이후 기록에 해당한다. 첫 입력이나 동률에는 부여하지 않는다.
- 업적도 현재 기록에서 계산해 관련 기록 삭제 시 조건에 맞게 해제한다.

홈에는 '레벨은 기록 습관의 누적입니다'를 짧게 표시한다. 신체·학습·생활 분류는 실제 능력 점수로 환산하지 않는다.

## 8. 화면 구성과 흐름

모바일 하단 메뉴는 상태창 / 기록 / 성장 / 설정 네 개다. 항목 추가는 기록 화면 상단에, 빠른 기록은 상태창과 기록 목록에 배치한다.

### 상태창

상단에 닉네임·레벨·XP 막대, 다음에 고정 성장 카드, 주간 목표, 최근 기록 순서. 화면 첫 영역에서 현재 상태와 기록 버튼을 찾을 수 있어야 한다.

```text
┌────────────────────────────┐
│ SOLO LEVELUP         설정  │
│ 나의 성장 기록       Lv. 3 │
│ 40 / 100 XP  ━━━━━────────  │
│                            │
│ 최근 변화       [7일 ▾]   │
│ 푸시업 최고  23회  +3회    │
│ 독서 합계   80쪽  +20쪽    │
│ 체중        76.5kg -0.3kg  │
│                            │
│ 이번 주 목표               │
│ 독서       80 / 100쪽      │
│ 스트레칭    2 / 3일        │
│                            │
│        [ + 기록하기 ]      │
│ 상태창  기록  성장  설정    │
└────────────────────────────┘
```

위 수치는 배치 설명용이다. 실제 첫 화면은 '첫 기록을 남겨보세요'와 항목 추가 버튼을 보여준다.

### 기록

검색·분류 필터 → 항목 목록 → 항목별 최근값과 빠른 입력. 체크형은 목록에서 완료 가능. 숫자형은 하단 입력 패널에서 값·날짜·메모 입력 후 저장한다. 항목 생성은 이름과 유형을 먼저 받고 '추가 설정'에서 단위·분류·목표를 설정한다.

### 성장

전체 항목 요약을 분류별로 표시한다. 항목을 누르면 기간 선택, 대표값/변화량, 그래프, 목표, 날짜순 원본 기록을 보여준다. 측정·최고 기록은 점/선 그래프, 누적·시간은 일별 막대, 체크는 7일 달력과 완료 일수를 사용한다.

### 설정

닉네임·시간대·분류 관리·보관 항목·백업/복원·전체 데이터 삭제. 로컬 저장 안내와 마지막 백업일을 표시한다. 복원은 형식 검증 후 교체될 항목/기록 수를 안내하며 기존 데이터 백업 다운로드를 제공한다. 첫 버전은 병합 없이 전체 교체하고 실패 시 기존 데이터는 유지한다.

## 9. 디자인 가이드

컨셉: 차분한 RPG 상태창. 모바일에서 읽기 쉬운 기록 도구를 바탕으로 레벨과 보상에만 게임 분위기를 강조한다.

| 요소 | 제안 |
| --- | --- |
| 배경 | 짙은 남색 #0B1020 |
| 카드 | #151D30, 경계선 #334155 |
| 본문 | #F1F5F9, 보조 글자 #A8B4CC |
| 주요 행동 | 보라색 #7C3AED 위 흰색 글자 |
| 달성 표시 | 청록 #5EEAD4 + 체크 아이콘/문구 |
| 오류 | 밝은 붉은색 #FDA4AF + 오류 설명 |
| 글꼴 | 시스템 한글 sans-serif, 본문 16px, 핵심 수치 28~32px |
| 간격 | 8px 기준, 화면 여백 16px, 카드 안쪽 16~20px, 모서리 16px |
| 조작 | 터치 영역 최소 44×44px, 모든 입력에 레이블 |

모바일 360px부터 가로 넘침 없이 사용. 넓은 화면에서는 왼쪽 메뉴와 2열 카드, 콘텐츠 최대 폭 1120px. 하단 메뉴가 입력 버튼을 가리지 않도록 안전 여백을 둔다.

색만으로 성장/하락을 표현하지 않고 변화량·단위·아이콘을 함께 표시한다. 차트에 텍스트 요약을 제공하고 키보드 포커스, 입력 오류, 모달 포커스 복귀를 지원한다. 구현 시 일반 텍스트 대비 4.5:1을 확인한다. 레벨업 효과는 짧게 한 번, 모션 줄이기 설정을 존중한다.

빈 기록, 비교 데이터 부족, 저장 실패, 보관 항목, 삭제 확인, 좁은 화면, 긴 항목명도 디자인 대상이다. 초기에는 오리지널 기하학 엠블럼을 사용하고 캐릭터 일러스트 제작은 미룬다.

## 10. 구현 구조 제안

- Next.js + TypeScript + Tailwind CSS, 그래프는 Recharts.
- IndexedDB를 Dexie로 관리. 클라이언트 저장 접근은 브라우저에서만 수행한다.
- 초기 서버·로그인·비밀키 불필요. 로컬 저장은 같은 브라우저/사이트 주소에서 유지되며 기기 간 동기화는 없다. 브라우저 데이터 삭제 시 사라질 수 있어 백업/복원을 포함한다.
- PWA 설치와 네트워크 없는 앱 재실행 보장은 다음 단계. 로컬 데이터 저장만으로 완전한 오프라인 지원을 주장하지 않는다.
- 저장 접근과 집계 계산을 UI에서 분리해 추후 Supabase로 교체 가능하게 한다.

데이터 구조:

| 엔티티 | 주요 필드 |
| --- | --- |
| Profile | id, nickname, timezone, createdAt |
| Category | id, name, color, order |
| Metric | id, name, kind, unit, direction, categoryId, goal, pinned, order, archivedAt |
| Entry | id, metricId, localDate, value, note, createdAt, updatedAt |
| Backup | schemaVersion, exportedAt, profile, categories, metrics, entries |

완료 체크 값은 1로 저장하며 취소 시 해당 기록을 삭제한다. 레벨·XP·업적·그래프 집계는 원본 기록에서 파생하며 별도의 중복 원장으로 저장하지 않는다. 백업 복원 시 버전·자료형·ID 중복·참조 관계·날짜·숫자 규칙을 검증하고 트랜잭션으로 적용한다. CSV는 스프레드시트 수식으로 해석될 수 있는 사용자 문자열을 안전하게 처리한다.

## 11. 작업 순서와 완료 조건

1. 화면 설계: 상태창·기록·항목 추가·성장 상세의 배치, 빈 상태와 예시 상태 검토.
2. 기록 기능: 데이터 모델, 기본 세트 선택, 자유 항목, CRUD, 브라우저 저장.
3. 성장 기능: 기간 집계, 비교, 그래프, 주간 목표, 고정 카드.
4. 게임 요소: XP·레벨·업적과 수정/삭제 후 일관성.
5. 사용 검증: 백업/복원, 모바일·키보드 조작, 오류 처리, 빌드 및 아래 핵심 시나리오.

명세 검토 다음 작업은 1번 화면 설계다. 초기 골격에 실제 동작을 붙인 다음 2주 체험으로 확장 여부를 판단한다. 정확한 개발 기간은 구현 환경과 검토 범위 확정 후 산정한다.

## 12. 인수 테스트

- 기본 세트를 선택하면 선택한 항목만 생성되고 실제 기록은 비어 있다.
- '기타 연습 / 시간 / 분 / 취미'를 추가하면 새로고침 후에도 항목과 기록이 유지된다.
- 독서 10쪽과 20쪽을 같은 날 기록하면 합계 30쪽, 해당 항목 XP는 10이다.
- 6개 항목을 하루 기록하면 50 XP이며 같은 기록 재저장으로 증가하지 않는다.
- 유효 기록 수정·삭제 후 통계·목표·XP·업적이 일관되게 재계산된다.
- 체중 같은 날 중복 입력은 기존 기록 변경을 안내한다. 체크 반복은 중복 기록을 만들지 않는다.
- 빈 구간은 비교 불가, 이전값 0은 퍼센트 미표시, 감소형 최고 기록은 최소값을 선택한다.
- 월요일 경계, 월말, 시간대별 자정에서 날짜와 주간 목표가 올바르게 계산된다.
- 보관한 항목의 데이터와 XP는 유지되고 활성 목록에서만 숨겨진다.
- 잘못된 백업은 거부하고 기존 데이터를 보존한다. 정상 백업 왕복 후 데이터와 집계가 같다.
- 360px 화면에서 핵심 조작이 가능하고, 숫자 키패드·키보드·오류 안내를 확인한다.
- 빌드/타입 검사, 집계 규칙 단위 테스트, 항목 생성→기록→새로고침→수정/삭제의 브라우저 테스트를 통과한다.

이번 산출물은 작업명세서다. 앱 기능 테스트나 실행 검증은 구현 이후 수행한다.
