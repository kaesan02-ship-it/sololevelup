# 제품 검토 및 실행 계획 · 2026-10-13

## 판정
개인용 기능 검증이 된 앱이지만 불특정 다수에게 정식 출시할 수준으로 인증·운영 준비가 완료된 것은 아니다. 이번 목표는 기존 기록을 보호하면서 소규모 사용성 테스트에 적합한 베타로 개선하는 것이다. 기존 자동화 통과는 실제 사용자의 재방문·이해도·장기 데이터 복구를 증명하지 않는다.

## 실행할 개선
1. 홈의 성장 단계/SVG 문장, 다음 단계 조건과 오늘의 선택 퀘스트 3개. 등록한 실제 항목으로 구성하고 미완료 페널티·추가 XP는 두지 않는다.
2. 실제 기록 저장으로 레벨이 오를 때 닫을 수 있는 축하 카드. 수치를 과장하거나 건강 상태를 평가하지 않는다.
3. 날짜별 선택 회고: 오늘 잘한 일, 남기고 싶은 이야기, 다음 작은 행동. 추가 XP 없이 수정·삭제·JSON 백업·동기화, 이전 백업 호환을 검증한다. 초안이 저장되었는지 명확히 알린다.
4. 설정에 베타/데이터 안내, 공개 피드백 창구와 기록 삭제 범위 안내. 로그인 중 비밀번호 변경 기능 제공.
5. 새 기능의 경계값/저장/복구 및 기존 모바일·사진·동기화 회귀 테스트, 배포 후 실제 주소 재검증.

## 정식 출시 전에 남는 조건
- 이메일 소유 확인 및 실제 메일 수신을 포함하는 비밀번호 복구: 현재 프로젝트는 이전 검사에서 이메일 자동 확인 상태. 공개 키로 관리자 설정을 바꿀 수 없다. SMTP·Site URL·Redirect URL 설정 후 실메일 테스트가 필요하다.
- 계정 탈퇴: 현재 앱 기록 초기화는 Auth 계정 삭제가 아니다. 서버에서 요청자 JWT를 확인하는 탈퇴 엔드포인트와 개인정보 보유/백업 삭제 정책, 실제 탈퇴 검증 필요. 관리자 키를 브라우저에 넣어 구현해서는 안 된다.
- 운영 주체·연락처·보유 기간·국외 처리 등을 확정한 개인정보 처리방침. 앱의 저장 방식 안내는 정식 방침을 대체하지 않는다.
- CAPTCHA/가입 남용 제어, 장애 알림, DB 백업 복원 연습, 사용량/비용 경보. 공유 Supabase 프로젝트의 다른 앱까지 검토해야 한다.
- 격리된 부하 테스트 및 안드로이드 실기기/아이폰 Safari 접근성 테스트. 현재 단일 JSON 문서 CAS 동기화는 소규모에 적합하며 수년치/대용량 사진에는 분리 저장이 필요할 수 있다.
- 5~10명 사용성 테스트로 첫 기록 성공률, 데이터 복구 성공, 1주 재사용 의향을 확인. 실제 사용자 분석/추적은 이번에 추가하지 않는다.

운영 설정/발신 도메인/관리 권한이 필요한 작업은 공개 키만으로 완료할 수 없다. UI 완성도를 이유로 출시 준비 완료라고 표시하지 않는다.

## 구현 및 검증 기록
- 성장 단계 4개, 등록 활동 기반 선택 퀘스트, 실제 XP 증가 시 레벨업 축하, 홈→하루 회고→날짜별 회고 조회 흐름 구현.
- 회고는 schemaVersion 1의 선택 필드로 추가. 기존 백업은 그대로 읽고 JSON 내보내기와 클라우드 payload에 포함한다. 구버전 앱과 동시 사용 시에는 먼저 새로고침을 권장한다.
- 동시 편집은 기존 CAS 저장 보호에 더해 회고를 열었을 때의 원본과 현재 내용을 비교한다. 충돌 시 입력 초안을 유지하고 저장을 거부한다.
- 현재 비밀번호 확인을 포함한 비밀번호 변경, 데이터 보관/초기화 범위와 베타 기능 안내, 공개 GitHub 피드백 창구 추가.
- 단위 테스트 25개, 기존 브라우저 19개와 새 회고/레벨업 흐름 통과. 모의 Supabase 두 기기 테스트에서 오프라인/충돌/회고 전달/비밀번호 변경 통과. npm audit 운영 의존성 알려진 취약점 0개.
- 저장된 textarea의 내용이 라벨 조회에 섞이던 문제를 명시적인 접근성 이름으로 수정했다. 실메일 복구·Auth 계정 삭제·운영 설정은 검증 완료로 표시하지 않는다.
- 추가 회고 동시 편집/360px 작성 검증을 포함하여 브라우저 시나리오 총 23개를 검증했다. 정적 export의 경로/폰트/기록/회고/오프라인 재접속 검사 1개도 통과했다. 이 검사는 GitHub 배포 워크플로에 추가하여 실패 시 배포를 차단한다.
